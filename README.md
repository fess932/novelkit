# rlib — ranobelib.me → EPUB

Скачивает главы книги с ranobelib.me с выбором команды перевода и собирает валидный EPUB 3
с нормальной разметкой (абзацы, курсив/жирный, цитаты, разделители, иллюстрации, оглавление).

## Зависимости

| Что | Зачем | Обязательно |
| --- | --- | --- |
| **Node.js 20.6+** | сама утилита | да |
| **ImageMagick 7** (`magick`) | сжатие иллюстраций по флагу `--compress` | нет |

npm-пакетов нет вообще: ни одной зависимости в `package.json`, `npm install` не нужен.
Скачивание, разбор контента и сборка EPUB (включая zip-архив) сделаны на штатных модулях Node.

ImageMagick нужен только для `--compress`. Без него всё работает, картинки просто кладутся
в книгу в оригинале. Поставить:

```sh
brew install imagemagick
```

Подойдёт и ImageMagick 6 (`convert`) — утилита сама выберет, что найдёт в системе.

## Установка

```sh
node bin/rlib.js --help
# или глобально:
npm link && rlib --help
```

## Использование

Проще всего запустить без аргументов — утилита спросит всё сама:

```sh
node bin/rlib.js
```

```
Что делаем?
 ❯  1. Скачать новую книгу     — по ссылке или названию
    2. Продолжить загрузку     — незавершённых: 1
    3. Собрать EPUB из кэша    — книг в кэше: 2
    4. Показать, что в кэше
```

Дальше — выбор книги из кэша (с прогрессом и командой перевода) и вопрос про сжатие
иллюстраций. Пункты про кэш появляются, только когда в нём что-то есть.

Всё то же самое доступно флагами:

```sh
# по ссылке или slug — дальше интерактивный выбор перевода и диапазона глав
rlib https://ranobelib.me/ru/book/26690--omniscient-readers-viewpoint-novel

# по названию (поиск, потом выбор из списка)
rlib "Всеведущего читателя"

# посмотреть, чьи переводы есть
rlib 26690--omniscient-readers-viewpoint-novel --list-branches

# без вопросов: конкретная ветка и диапазон
rlib 26690--omniscient-readers-viewpoint-novel --branch 17824 --from 1 --to 100 --yes

# ветку можно выбрать по названию команды
rlib 26690--omniscient-readers-viewpoint-novel --branch-name "Волк на псарне" --yes
```

## Выбор перевода

У одной книги на сайте обычно несколько веток — это те самые вкладки над списком глав.
`--list-branches` показывает их ровно так же, как сайт:

```
id=9824   550 гл.  Silent Step & Эрл Грей («Ничоси 2») [Theunt, AtLas, YuraFissura]
id=9823   301 гл.  Kyu Team & Rulate Project & FiuTeam («Ничоси 1») [Кьюджин, …]
id=11722   17 гл.  Aniker Team & Lipov Team («Webfandom») [Andrey Lipov]
id=26435  нет глав  Альтернативный перевод
```

Подписи берутся из карточек веток (`/api/branches/<id>`) — там перечислены все команды ветки.
В скобках — внутреннее имя ветки, в квадратных — те, кто заливал главы. Ветка может числиться
на сайте вкладкой, но не содержать ни одной главы: в списке она видна как «нет глав», выбрать
её нельзя.

Ветка попадает в метаданные книги: `dc:contributor` и строка «Перевод:» на титульной странице.

## Остановка и продолжение

Загрузка **останавливается на первой неустранимой ошибке** — код возврата 1, скачанное остаётся
в кэше задания (`.rlib/<slug>--b<branch>/`). Продолжение подхватывает ровно с места обрыва:

```sh
rlib --resume                       # последнее незавершённое задание
rlib --resume .rlib/26690-...--b17824
rlib --list-jobs                    # что вообще недокачано
```

Кэш хранит сырые ответы API по главам, поэтому повторная сборка EPUB не тратит ни одного запроса:

```sh
rlib --resume <каталог> --build-only
```

Расширение диапазона тоже бесплатно: если запустить ту же книгу с `--to 200` после `--to 100`,
докачаются только новые главы.

## Сжатие иллюстраций

Сайт отдаёт картинки в оригинале — до 3600 px по стороне и по 3–5 МБ штука, поэтому книга
с иллюстрациями легко весит сотни мегабайт. Флаг `--compress` пережимает их при сборке:

```sh
# пересобрать уже скачанное, ничего не качая заново
rlib --resume .rlib/14841--beginning-after-the-end-novel--b9824 --build-only --compress
```

Реальный пример — 353 главы, 318 иллюстраций:

| | вес книги | картинки |
| --- | --- | --- |
| без сжатия | 263 МБ | 248.1 МБ |
| `--compress` | **27.8 МБ** | 24.0 МБ (−90%), ~30 с |

Настройки: `--max-image 1200` (большая сторона, по умолчанию 1200 px — больше экрана любой
читалки) и `--quality 82`.

Оригиналы в кэше остаются нетронутыми: сжатые копии складываются рядом в
`assets-jpeg-<размер>-<качество>/`, поэтому повторная сборка с теми же настройками мгновенная,
с другими — создаёт отдельный каталог, а без `--compress` книга снова соберётся из оригиналов.

Что учтено: картинки с прозрачностью не переводятся в jpeg (фон стал бы чёрным) — они остаются
png и только уменьшаются; `gif` и `svg` не трогаются; если пережатый файл вдруг тяжелее
исходного, берётся исходный; EXIF срезается, ориентация применяется заранее.

## Пауза между запросами

Между запросами выдерживается пауза `--delay` плюс случайная добавка `--jitter`
(по умолчанию 1500 + 0…700 мс). Запросы идут строго последовательно, без параллельности.

При `429`/`503` утилита ждёт `Retry-After` (или экспоненциальный бэкофф), увеличивает базовую
паузу в 1.7× и затем плавно возвращает её к исходной. Если рейт-лимит всё равно ловится —
`--delay 4000`.

## Опции

| Опция | Значение |
| --- | --- |
| `--branch <id>` | id ветки перевода |
| `--branch-name <строка>` | ветка по названию команды (подстрока) |
| `--list-branches` | показать ветки и выйти |
| `--from <n>` / `--to <n>` | диапазон глав по порядку внутри ветки |
| `--out <файл>` | путь к .epub (по умолчанию — по названию книги) |
| `--work-dir <кат>` | каталог кэша заданий (по умолчанию `.rlib`) |
| `--delay` / `--jitter` / `--retries` | темп запросов и число повторов |
| `--no-images` | не скачивать иллюстрации |
| `--compress` | сжать иллюстрации при сборке (нужен ImageMagick) |
| `--max-image <px>` / `--quality <1-100>` | параметры сжатия (1200 / 82) |
| `--build-only` | собрать EPUB из кэша, ничего не качая |
| `--resume [кат]` | продолжить прерванную загрузку |
| `--list-jobs` | список заданий в кэше |
| `--yes` | без вопросов (берётся самая полная ветка и все главы) |

## Что внутри EPUB

- титульная страница: название, оригинальное название, автор, команда перевода, жанры, аннотация;
- обложка с сайта;
- глава = отдельный XHTML-файл, заголовок вида «Глава 1.2. Название»;
- оглавление в двух форматах: `nav.xhtml` (EPUB 3, с группировкой по томам, если томов больше
  одного) и `toc.ncx` для старых читалок;
- иллюстрации главы вместе с примечаниями переводчика к ним;
- типографская вёрстка: абзацный отступ, выключка по ширине, переносы, стили для цитат и
  примечаний (`styles/main.css`).

Сайт отдаёт контент глав в двух разных форматах (ProseMirror JSON и HTML) — оба приводятся к
одному чистому XHTML: неизвестные теги разворачиваются (текст не теряется), скрипты и стили
выбрасываются, незакрытые теги закрываются.

## Ограничения

- Платные и недоступные главы отдают 4xx — загрузка на них останавливается; такие главы можно
  пропустить, сузив диапазон (`--from`/`--to`).
- Картинка, которая не скачалась, не роняет задание: она пропускается, предупреждение пишется в
  `state.json` и в вывод.
